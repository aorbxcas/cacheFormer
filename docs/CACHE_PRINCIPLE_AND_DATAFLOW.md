# 块级缓存：原理与数据流

## 一、为什么用「块级」、且插在视图无关层之前？

### 1. 视图无关层输出的性质

RenderFormer 的**视图无关层**是一整段序列上的 **全局 self-attention**（12 层 Transformer）：

- 输入：每个三角形一个 token（几何 + 材质编码）。
- 输出：每个三角形的 token 已经和**全场景所有三角形**交互过（光传输、遮挡、间接光都耦合在一起）。

因此：

- 视图无关层**之后**的向量是**全局属性**，不能按「单三角形」或「单块」拆开复用：同一几何在不同场景里，邻居不同，输出就不同。
- 若在视图无关层**之后**做缓存，只能以「整场景」为 key，无法按块失效、也无法跨场景复用同一物体。

### 2. 插入位置：视图无关层「之前」

我们把缓存做在**视图无关层之前**，对「一组三角形」先做编码，得到**块级中间表示**（只依赖该块自己的几何+材质），再：

- 以**块指纹**为 key 做缓存 → 同一块在不同场景、不同帧可以复用。
- 对重组后的**块序列**再做全局 attention（现有 12 层 Transformer），这样语义正确，且能按块失效。

也就是说：**缓存的不是全局光照结果，而是「块自己的编码」**；全局光照仍在后面的 Transformer 里算。

---

## 二、块是什么？键与值是什么？

### 1. 块（Block）

- **定义**：一组三角形的集合。当前实现里按**索引**均匀切分，例如每 256 个三角形一块（`block_size=256`）。
- 可选扩展：按物体 / mesh / 材质分组，这样同一物体在不同场景里天然是同一块，跨场景复用更好。

### 2. 缓存键（Key）

- **含义**：这一块几何+材质的**指纹**，与相机、视角、场景中其他块无关。
- **输入**（仅用该块）：
  - `tri_vpos`：三角形顶点 [1, N_b, 9]
  - `texture`：纹理块 [1, N_b, 13, 32, 32]（哈希时对空间维做 mean 压缩）
  - `vn`：顶点法线 [1, N_b, 9]
- **算法**：上述张量规范化后拼成连续 float32 字节流，做 **MD5 取前 16 字节**，得到 128 位 key。
- **性质**：同一块（相同几何+材质）在不同帧、不同场景会得到**相同 key**，从而命中缓存。

### 3. 缓存值（Value）

- **含义**：这一块在「视图无关层之前」的**三角形 token 序列**（即 `construct_seq` 里得到的三角形部分，不含 reg_tokens）。
- **形状**：`[1, N_b, 768]`，即该块内每个三角形一个 768 维向量（几何+材质编码，尚未做全局 attention）。
- **性质**：只依赖该块自身输入，所以可以安全地按 block_key 复用。

## 三、整体数据流（带缓存的渲染路径）

下面用「单帧、batch=1」说明；多帧时重复同一流程，第二帧起同一块的 key 会命中缓存。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 输入：triangles [1, N, 3, 3], texture [1, N, 13, 32, 32], vn [1, N, 3, 3],   │
│       mask [1, N], c2w [1, nv, 4, 4], fov [1, nv, 1]                        │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 预处理（与无缓存路径一致）                                                     │
│ • texture：必要时 log 编码光照分量                                            │
│ • tri_vpos = triangles.reshape(1, N, 9), vn_flat = vn.reshape(1, N, 9)      │
│ • 相机/视角：trans_to_cam_coord、ray_generator → rays_o, rays_d,             │
│   tris_for_view_tf（供后续视图相关层用）                                       │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 块划分                                                                       │
│ • 按索引切块，例如 block_size=256 → 块 0: [0:256], 块 1: [256:512], ...     │
│ • 每块得到：tri_vpos_b, texture_b, vn_b, mask_b                              │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 逐块：哈希 → 查缓存 → 未命中则编码 → 写回缓存                                 │
│                                                                             │
│   for (start, end) in blocks:                                               │
│     block_key = compute_block_hash(tri_vpos_b, texture_b, vn_b)   [16 字节] │
│     cached = block_cache.get(block_key)                                      │
│     if cached is not None:                                                   │
│         tri_emb_b = cached.to(device)     # 命中：直接用缓存的 [1, N_b, 768] │
│     else:                                                                    │
│         seq_b, _, _ = model.construct_seq(tri_vpos_b, texture_b, mask_b,   │
│                                            vn_b)                            │
│         tri_emb_b = seq_b[:, skip_token_num:, :]   # 只取三角形部分          │
│         block_cache.put(block_key, tri_emb_b)     # 未命中：编码后写入       │
│     tri_emb_list.append(tri_emb_b)                                            │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 重组为整场景序列                                                             │
│ • tri_emb_full = concat(tri_emb_list)          → [1, N, 768]                 │
│ • seq_full = [reg_tokens | tri_emb_full]      → [1, 16+N, 768]              │
│ • tri_vpos_list, valid_mask_padded = process_tri_vpos_list(tri_vpos_full,   │
│                                                            mask_full)       │
│   → 为 RoPE 等提供位置与 mask，形状 [1, 16+N, …] / [1, 16+N]                │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 视图无关层（全局，不跳过）                                                     │
│ • seq_out = transformer(seq_full, valid_mask_padded, triangle_pos=tri_vpos)  │
│ • 输入是「整场景」的 token 序列，输出仍是 [1, 16+N, 768]                      │
│ • 这里做 12 层 self-attention，得到带全局光照的三角形表示                     │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 视图相关层（与无缓存路径一致）                                                 │
│ • seq_out 按视角复制，与 rays、tri_vpos_view_tf 一起送入 view_transformer    │
│ • 输出：rendered_imgs [1, nv, H, W, 3]                                       │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 后处理                                                                       │
│ • 必要时 log 解码、permute、保存 / 返回                                       │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 四、关键点小结

| 环节 | 说明 |
|------|------|
| **缓存的阶段** | 只缓存「块编码」：`construct_seq` 对单块得到的三角形 token，**不**缓存 12 层 Transformer 的输出。 |
| **键** | 块内几何+材质的 128 位哈希，与相机无关；同一块在不同场景/帧 → 同一 key → 可复用。 |
| **值** | 该块的 tri_emb [1, N_b, 768]，即视图无关层**之前**的 768 维 token。 |
| **重组后** | 依旧走完整的「全局 Transformer + 视图相关层」，所以光照与无缓存路径一致。 |
| **命中效果** | 命中时跳过该块的 `construct_seq`（编码器 + 块内位置处理），减少重复计算；第二帧同场景时通常全部命中。 |

---

## 五、与无缓存路径的对比

- **无缓存**：每帧对整场景做一次 `construct_seq`（整序列）→ 一次 `transformer` → `view_transformer`。
- **有缓存**：每块先查 key；命中则直接用缓存的 tri_emb，未命中则对该块做 `construct_seq` 并写入缓存；然后**拼接成整场景序列**，再执行**同一条** `transformer` + `view_transformer`。

因此：**数学上与无缓存等价**，只是「三角形编码」这一步按块做了缓存与复用，全局光照和视角相关部分没有省略。
