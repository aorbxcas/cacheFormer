# 游戏引擎领域：性能优化方向

> **版本**：1.0  
> **状态**：设计落档，待选型实现  
> **关联**：[`C1_residual_indirect_head.md`](./C1_residual_indirect_head.md)、[`scheme4_hybrid_gi_plan.md`](./scheme4_hybrid_gi_plan.md)、[`project_c_quality_controlled_neural_gi.md`](./project_c_quality_controlled_neural_gi.md)、[`实验记录_同场景VI缓存.md`](./实验记录_同场景VI缓存.md)  
> **定位**：若将 CacheFormer 应用于游戏引擎（编辑器预览 / 运行时近似 GI 插件），相对通用推理加速，还有哪些**该领域特有**的性能优化方向。

---

## 0. 结论摘要

进引擎时，真正可挖的不是再抠 FlashAttention，而是把「**全场景每帧 feed-forward GI**」改成引擎惯用的「**Direct 跟帧 + Indirect 缓冲 / 预算 / 分区**」。

| 现状事实 | 含义 |
|----------|------|
| Runtime Direct 已是毫秒级 | 与引擎光栅同路；不是帧率瓶颈 |
| VI Cache 命中后主瓶颈在 **VD** | 交互预览约 5–15 FPS 量级（VD@256），通常达不到 60 FPS@1080p |
| 整场景指纹一动全 miss | 玩法场景下「仅相机变」假设经常不成立 |
| 块级 VI 缓存实验命中率近 0 | 全局 attention 下不宜指望简单「按三角 LRU」 |

**一句话**：CacheFormer 应从「每帧神经渲染器」变为「**间接光缓冲的异步填充器**」；通用算子加速只是锦上添花。

## 1. 产品形态假设

| 假设 | 说明 |
|------|------|
| 形态 | 编辑器预览 / 运行时近似 GI **插件**，非替代 Lumen/DDGI 的生产方案 |
| 优先级 | 帧率与跟手 > 离线电影级 Indirect |
| 分工 | 引擎光栅负责 Direct；神经腿填充 / 刷新 `I_buffer` |
| 验收 | 交互跟手；静止或松手后间接可收敛；动态不承诺满配每帧 II |

推荐运行时环：

```text
每帧（同步、跟玩法）：
  1. 引擎光栅：Albedo / Depth / Shadow → L_direct
  2. 查间接缓冲（上一帧或异步结果）
  3. L = L_direct + α · I_buffer   （线性空间；tonemap 交给引擎）

异步 / 降频（不阻塞呈现）：
  - 静物 VI 命中 → 只更新动态相关 + 小头（C1）
  - 或：每 N 帧 / 每帧预算内 tile 刷新 I_buffer
  - 相机大裁、传送、关卡流式加载 → 强制 miss，短时 Direct-only
```

---

## 2. 方向一：帧预算与调度（引擎最核心）

引擎有固定帧时间，不能「算完再显示」。

| 方向 | 动机 | 做法草案 |
|------|------|----------|
| **间接缓冲 + 隔帧** | 神经腿跟不上 60Hz | 每帧只合成 `L_direct + α·I_buffer`；II 每 N 帧或静止后刷新 |
| **交互档 / 质量档** | 拖拽、冲刺要跟手 | 交互：Direct-only 或 Direct + warp 上帧 II；松手/镜头停：补全 II |
| **每帧 ms 预算切片** | 固定算力配额 | 每帧最多更新 N% 像素或固定 tile；其余复用上一帧 II |
| **异步 compute 队列** | 现同步 Python 管线 | Direct 在渲染线程；RF/小头进 async；合成永远用上一帧就绪结果 |
| **时间切片 VI/VD** | 一帧算不完整段 Transformer | 多帧摊销：帧 0 编码，帧 1 半层 VI，帧 2 VD… |

与 C1「Direct 跟玩法、Indirect 可降频」一致；相对现状属 **P0**。

---

## 3. 方向二：缓存键与失效粒度

整场景指纹适合「场景不变、仅相机变」；玩法场景需要更细失效。

| 方向 | 现状问题 | 引擎向改法 |
|------|----------|------------|
| **静/动分层缓存键** | 一物体位移 → 全场景 miss | 静态关卡几何永命中 VI；动态 Actor 单独 invalidate |
| **世界分区 / Streaming** | 大关卡无法整场景 VI（≤~4096 三角） | 按 cell / sublevel 缓存；只激活玩家邻域 |
| **运动向量驱动局部失效** | 物体一动全量重算 | 仅刷运动物体相关 token/区域；静物保留（需分层 VI 或 C1-b） |
| **灯光失效策略** | 动态灯常见 | 玩法灯 / 枪口火光优先只进 Direct；II 用保守 α 或延迟刷新 |
| **引擎 dirty 事件** | 研究管线每帧重算 fingerprint | 订阅物体/灯/流式加载 dirty，按事件失效 |

> 实验已表明：在全局 attention 下「按三角小块缓存 VI」命中率近 0。引擎侧应走 **分层失效 + 间接缓冲**，而非简单块级 LRU。

---

## 4. 方向三：分辨率与屏幕空间（GBuffer 红利）

引擎本就有深度、法线、运动向量、粗糙度。

| 方向 | 动机 | 做法草案 |
|------|------|----------|
| **屏幕空间低分 II** | 头/VD 不必吃全分辨率 | II @ 1/4～1/2，双边/棋盘上采样；Direct 全分辨率 |
| **Camera / reprojection warp** | 镜头转动时 II 延迟可接受 | 用 motion vector 重投影上帧间接，异步补洞 |
| **GBuffer 条件化小头（C1）** | 少依赖全量 RF | 头输入加 depth、N、motion、Roughness |
| **棋盘 / 交错刷新** | 平滑摊销预算 | 奇数帧刷一半 tile，观感更跟手 |
| **与引擎 Tonemap 对齐** | 避免 HDR 合完再崩 | 线性空间融合；tone map 交给引擎后处理 |

---

## 5. 方向四：与引擎 GI 栈混用

| 方向 | 说明 |
|------|------|
| **近景 / 室内 / 关键卡区** | CacheFormer / C1 填高价值间接 |
| **远景 / 大开图** | 探针、DDGI、SSR、环境光 |
| **降级阶梯** | miss → Direct only → 低分 II → 满分 II（可玩性优先） |
| **固定点 / 探针混合** | 纯 feed-forward 难覆盖超大场景；远景探针、近景 C1 |

产品目标是**并存与补位**，不是硬刚生产级 GI。

---

## 6. 方向五：内容与三角预算（资产管线）

RF 的 \(O(N^2)\) attention 与约 4096 三角上限是硬约束。

| 方向 | 做法草案 |
|------|----------|
| **导入 remesh / 代理网格** | FBX/glTF → 自动压到预算三角；高模只给 Direct |
| **Imposter / 静物合批** | 远处合为低三角 proxy 进 VI |
| **预烘焙静物 VI 特征** | 关卡加载时热启，避免首次漫游卡顿 |
| **材质分布收敛** | 优先不透明 GGX；透明 / SSS 仍走引擎原路径 |

研究管线的 H5/JSON 需换成引擎内容流水线，否则无法进关卡。

---

## 7. 方向六：架构向（让「可缓存」成立）

若动态物体也要神经间接，需比现 Hybrid「事后分解」更进一步。

| 方向 | 归属 | 说明 |
|------|------|------|
| **C1 残差间接头** | C1 | 语义上只出 II，才方便降频 / 缓存而不每帧跑全 RF |
| **VD 自适应调度** | 项目 C | 粗分辨率 + 重要性 refine，算力砸在屏幕变化大区域 |
| **分层 / 稀疏 attention（中长期）** | 模型侧 | 静物 KV + 动态 query；否则动景 VI 仍难局部复用 |
| **Direct 语义分离** | C1 + Hybrid | Hybrid 是拼盘；C1 让神经腿只负责间接，调度才干净 |

---

## 8. 优先级建议

| 优先级 | 项 | 归属 |
|--------|----|------|
| **P0** | Direct 每帧 + 间接缓冲复用 / 隔帧 | CacheFormer 调度 |
| **P0** | 交互档 Direct-only | CacheFormer / 引擎集成 |
| **P1** | C1-a 残差头（证明 II 可学） | C1 |
| **P1** | 静/动几何分缓存键 | CacheFormer |
| **P2** | C1-b 特征头 + VI 缓存喂头 | C1 + Cache |
| **P2** | 屏幕空间低分 II + motion warp | 引擎向 |
| **P2** | 每帧 tile 预算 + 异步队列 | 引擎向 |
| **P3** | 大世界分区 / 与 DDGI 混合 | 产品化 |
| **P3** | 内容 remesh / 预烘焙 VI | 内容管线 |

## 10. 非目标

- 承诺 60 FPS @1080p 满配神经 GI  
- 替代引擎内置 Lumen / DDGI 生产方案  
- 首期支持透明 / SSS / 复杂环境光间接  
- 用块级 LRU 单独「解决」全局 attention 下的 VI 复用  

---

## 11. 总结

| 问题 | 回答 |
|------|------|
| 引擎里该优化什么？ | 帧预算、缓存失效粒度、GBuffer/屏幕空间、与引擎 GI 混用、内容三角预算 |
| 不该优先抠什么？ | 仅通用算子加速而仍每帧跑全 RF |
| CacheFormer 角色 | 间接缓冲 + 分区失效调度器 |
| C1 角色 | 填间接缓冲的学习器（Indirect 可降频） |
| Direct 角色 | 永远跟帧，由引擎光栅 / Runtime Direct 负责 |
